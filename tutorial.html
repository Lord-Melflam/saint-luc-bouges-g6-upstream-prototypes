Tutorial

How to use the Upstream Prototype

This page explains the workflow, the data model, and how every panel reacts to the patient you have selected.

Forecast & Coordination Operations Matrix Tutorial

1) End-to-end workflow

  1. Open Forecast & Coordination and either fill the Forecast & Input Panel or click Seed demo data to bootstrap four example patients.
  2. Click Add patient & Sync. The system generates the patient ID (P-LIVE-NNNN), computes LOS + confidence, and tries to place the patient in a bed.
  3. If a preferred bed is unavailable in the selected service, the patient is queued (with reason + timestamp) instead of failing.
  4. Click any patient row in Patient registry, the Queue, the Threshold-at-risk list, or the Nurse station to focus that patient. Every patient-aware panel below updates: Communication Hub, Stakeholder Feed, Tutorial & Demo script, Control Tower focus.
  5. Open Operations Matrix to inspect beds, the queue, and to discharge or reassign.
  6. From an occupied bed, Modify patient in Forecast page sends you back to the Forecast page in edit mode, where you can confirm or decline the update with an optional LOS recompute.

2) Forecast inputs explained

  • Procedure type : drives an automatic mapping to service and specialty (those fields are read-only and follow the procedure choice).
  • Severity index type : Charlson or Elixhauser framing (replaces the old comorbidity wording, per stakeholder feedback).
  • Severity score : 0–15 intensity. Influences both LOS and confidence.
  • Age, gender, social complexity, post-acute need : modify the LOS prediction and the confidence label (high / medium / low).
  • Primary blocker : medical / admin / transport / family / logistics / none. Routes to a different stakeholder owner in the alert mapping.
  • Planned departure time (D0) : measured against the discharge cutoff (12:00). Yields safe / info / warning / critical threshold risk.
  • Bed type + policy:
    • strict : queue if the preferred bed type is not free in the service;
    • flexible : accept an alternative bed type and record a data-quality warning.
  • IDAG / DMG : optional grouping placeholders from stakeholder notes; informational only.

3) Adding patients & duplicate detection

  • Patient IDs are system-generated. There is no manual ID input.
  • If you click Add patient & Sync with form fields that already match an active patient (name, age, gender, procedure type/subtype, service, severity index/score), the prototype does not create a duplicate. It tells you which existing patient matched and switches focus to it.
  • To create a different person who happens to share clinical fields, change the patient name (or any other identifying field) and re-submit.
  • Simulation presets are the explicit exception: they intentionally spawn a fresh stress event each click, even when the inputs collide. The duplicate name is auto-suffixed ((2), (3), …) so the same scenario can be repeated.
  • Reset state wipes the prototype's localStorage after a confirmation. Use it to start a clean demo or to recover from a bad state.

4) Outputs explained

Example forecast output for a focused patient:

patient_id: P-LIVE-0007
patient_name: Patient X
predicted_los_days: 5
severity_index: charlson=4
gender: female
expected_discharge_date: 2026-05-12
planned_departure_time: 11:00
assigned_bed: ORTH-O1-B1
threshold_risk_status: safe
billing_loss_risk: no
data_quality_warnings: none
  • assigned_bed: none : patient is queued, not rejected. Open Operations Matrix to assign manually.
  • threshold_risk_status : distance to the 12:00 discharge cutoff. warning < 30 min before cutoff, critical after cutoff.
  • billing_loss_risk: yes : planned departure is after the cutoff, so the day's bed-night may not be reimbursable.
  • data_quality_warnings : operational facts (preferred bed type unavailable, missing subtype, blocker without detail).

The Communication Hub renders a nurse handover script and an SMS timeline (D-2 / D-1 / D0) from the same patient state.

5) Selection drives every panel

  • The selection pill at the top of the Forecast page shows the focused patient (id, name, unit, bed, threshold) with a Deselect button.
  • Clicking any patient row in the Patient registry, Queue, Threshold-at-risk list, or Nurse station sets that patient as the focus. Every patient-aware panel updates in lockstep:
    • Communication Hub : nurse script, SMS, comm windows.
    • Stakeholder Update Feed : bed assignment, threshold owner, blocker owner, comm windows.
    • Upstream Control Tower : global occupancy + a focus subsection (queue position, bed status).
    • Tutorial & Demo script : switches from a generic flow to a per-patient cheat sheet.
  • Adding a patient automatically focuses the new patient. Editing a patient (via the Operations Matrix handoff) also focuses it.

6) Operations Matrix usage

  • Service view filter : global by default; switching to a service narrows both the bed matrix and the occupancy chart at the top.
  • Click any bed tile to inspect details on the right.
  • Occupied bed: Modify patient in Forecast page (opens edit mode) or Discharge patient (frees the bed instantly).
  • Free bed: pick a queued / unassigned patient and assign directly.
  • The Occupancy overview chart shows percent occupancy per service (or for the focused service when filtered), with proper Y-axis ticks (0/25/50/75/100%) and color thresholds (green < 50%, yellow ≤ 75%, red > 75%).

7) Role modes & Nurse station

  • Planner : full Forecast & Input Panel + every coordination card.
  • Nurse : the input panel is hidden; the page becomes a read-first board.
  • The Nurse station stat chips show active patients, unit load, queue depth, and threshold alerts.
  • Filters: unit (per-service or all), scope (active or all). The patient list and dropdown both honour the filters.
  • Clicking a patient on the left selects it. If the selected patient is filtered out, the right-hand detail panel says so instead of silently switching.

8) Simulation presets

Stress-test the dashboard with one click:

  • Late transport : pickup delayed; threshold risk rising.
  • Unresolved blocker : admin/medical paperwork pending past D0.
  • Late medical validation : physician sign-off slips after the cutoff.
  • Occupancy spike : adds emergency-service load.
  • Missing critical data : flags data-quality warnings instead of failing silently.

Each click spawns a fresh patient (auto-suffixed name) so you can stack multiple stress events. Recommended demo flow: baseline patient → trigger preset → observe queue / occupancy / risk changes in the Operations Matrix.

9) Monitoring panel (forecast occupancy)

  • Now full page width on the Forecast page so X-axis labels and point values never overlap.
  • Y axis : active-patient count with nice-tick spacing (0/2/4/… or 0/5/10/…).
  • X axis : days from today; ~8 labels max, rotated, formatted D5 04-17.
  • Every data point has a count label permanently visible, no hover required.
  • Focus service filter narrows the line to one service; Forecast horizon rescales the X axis (default = current max LOS in the registry).
  • Canvas is rendered with devicePixelRatio scaling, so lines and text stay crisp on high-DPI displays.

10) Bed types explained

Every bed in the system has a type that determines care capability and cost:

  • Standard ℹ : baseline bed type; supports most patients. Cost baseline.
  • Monitoring ℹ : equipped with continuous vital signs. For cardiac, stroke, or escalated acuity. +15% cost.
  • Premium ℹ : private room, specialized nursing, isolation capability. For VIP, infectious, or palliative. +30% cost.

Selection: When booking a patient, choose a bed type based on their condition. If the preferred type is not available in the selected service, the patient is queued with a reason (e.g., "monitoring bed unavailable in emergency"). Reserve beds can help fill gaps.

11) Severity index (Charlson Comorbidity Score)

The Charlson score quantifies a patient's medical complexity based on comorbidities:

  • Scale : 0–15 (higher = more severe).
  • 0–2 : low risk. Most common (60%+ of admissions).
  • 3–5 : moderate risk. Increased monitoring recommended.
  • 6–15 : high risk. Requires frequent escalation checks, dedicated nursing.

Impact on LOS : The system multiplies base LOS by a severity factor (1.0 + severity × 0.1), so a Charlson=4 patient stays ~40% longer. A Charlson=8 patient doubles the baseline LOS.

In the system: Input the intensity (1–5 scale) in the Forecast & Input Panel, and the Charlson score is auto-computed and displayed. This feeds the LOS prediction and threshold risk assessment.

12) LOS (Length of Stay) calculation

The system predicts how many days a patient will occupy a bed:

Formula:
Base LOS (procedure-specific) × Severity factor × Gender adjustment
Severity factor = 1.0 + (Charlson score × 0.1)
Gender adjustment = 1.05 if female, 1.0 if male  (typical clinical finding)

Example : Hip replacement (base 5 days) + Charlson 4 + female = 5 × 1.4 × 1.05 = 7.35 days → rounds to 7 days.

In practice :

  • LOS is computed at booking time.
  • It drives the expected discharge date (admission date + LOS).
  • It is not automatically recomputed if you update the patient later (to avoid phantom discharges). Click "Recompute LOS" manually in edit mode if patient comorbidity changes.
  • The monitoring chart uses the maximum LOS in the current cohort as the default forecast horizon.

13) Reserve beds system

When a service reaches full capacity (all 20 beds occupied), you can assign reserve beds to temporarily expand it:

  • Total pool : 12 reserve beds (2 per service × 6 services). Shown in the Reserve Pool section at the bottom of the Operations Matrix.
  • Per-service limit : max 2 reserve beds assigned to any single service at a time.
  • Visual indicator : Assigned reserves appear as an orange badge under the service name. The Reserve Pool shows remaining available beds.
  • Workflow :
    1. Click a reserve bed in the Reserve Pool section.
    2. A dropdown appears asking which service needs it.
    3. Confirm the assignment. The reserve bed is now added to that service's capacity (21/20 becomes 22/20).
    4. To unassign, click a free bed in that service and choose "Unassign 1 reserve bed" if reserves are assigned. The bed returns to the pool.
  • Data tracking : Reserve assignments persist in localStorage. Reload the page, and the assignments remain intact until you click Reset.

14) Auto-assign feature (queue management)

If the queue grows (many patients waiting for bed assignment), use the Auto-assign from queue button:

  • What it does : Scans the waiting queue and tries to place each patient in the next available free bed in their preferred service.
  • Priority : Processes queue in order (FIFO by timestamp). If no beds are available in the preferred service, the patient remains queued.
  • Outcome : Shows a toast notification with the count of successfully assigned patients (e.g., "✓ Auto-assigned 3 patient(s)"). The Operations Matrix updates in real-time.
  • When to use : During shift changes, occupancy spikes, or after bulk discharge (e.g., end-of-morning-shift). Reduces manual clicking for routine placements.

15) Patient status workflow

Every patient progresses through states:

  • pending : just created, awaiting bed assignment or confirmation.
  • queued : preferred bed type/service unavailable; waiting for manual assignment or reserve expansion.
  • booked : assigned to a bed; monitoring active.
  • discharged : patient left; bed is now free for next admission.

Transitions : pending → queued (if no bed available) or pending → booked (if bed available). booked → discharged (click "Discharge patient" in Operations Matrix). queued → booked (manual assignment or auto-assign). Editing a patient does not change state.

16) Error handling & data consistency

The system validates data to prevent inconsistencies:

  • Duplicate prevention : On patient creation, the system checks for duplicates (same name + age + gender). If found, a warning is shown and the patient is not added.
  • Bed conflicts : If a bed is already occupied, you cannot reassign it. The Operations Matrix prevents double-booking.
  • Queue ordering : Patients in the queue are ordered by timestamp (earliest first). If you manually assign a queued patient, it is removed from the queue automatically.
  • Threshold enforcement : If the expected discharge time slips past 12:00, the threshold status flips from safe → warning → critical. The billing loss risk is set to yes if discharge is after cutoff.
  • Data quality warnings : Flagged in the patient detail if missing procedure subtype, invalid gender, or bed unavailable. These do not block patient creation; they are informational.

Use these texts in SMS, email, or in-person handoff to align the care team on timing and blockers.

18) Tips & troubleshooting

  • Patient appears in multiple panels : By design. Selection is global; clicking any patient in the Registry, Queue, Threshold list, or Nurse station syncs all panels.
  • Why is my patient still queued after booking? : Check the bed type. If you selected a "monitoring" bed but none are available in the chosen service, the system queues the patient. Assign a standard bed manually, or request a reserve bed and reassign.
  • Occupancy chart not updating : Toggle the service filter (e.g., from "Global" to "Cardiology" and back). The chart refreshes on filter change.
  • Lost patient data on page reload? : All data is saved to localStorage. If the browser's local storage is cleared (privacy mode, cookie deletion), data is lost. The "Reset" button in Operations Matrix also clears everything; use it only for testing.
  • Reserve beds won't assign : Ensure the target service is at or above capacity (20/20 or higher). Reserves only assign to full services. Also, no more than 2 per service.
  • Toast notifications not showing : Check browser DevTools console for errors. Toasts appear bottom-right for 2.5 seconds and auto-hide.
